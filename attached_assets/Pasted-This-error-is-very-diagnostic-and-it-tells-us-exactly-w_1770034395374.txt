---

## What the error is really saying

> `64 × locator resolved to hidden <input type="text" placeholder="Search…" id="vendor-search-handler">`

This means:

* Playwright **did find** an `input[type="text"]`
* But it’s finding **the cookie consent vendor search box**
* That input is:

  * hidden
  * not the login field
  * injected very early into the DOM
* And because it’s first in DOM order, `.first()` grabs it

So Playwright is doing what you asked, but you asked too generically.

---

## Why this happens on Access / People Planner

Access sites load a **cookie consent manager** (OneTrust-style) that includes:

* hidden inputs
* search boxes
* vendor filters

These appear **before** the login form in the DOM.

Humans never see them. Automation does.

So this selector is now wrong:

```ts
page.locator('input[type="text"]').first()
```

---

## The correct mental model now

For login screens on this site:

* ❌ Never use “first input[type=text]”
* ❌ Never use global selectors
* ✅ Always scope to the **login form**
* ✅ Or exclude cookie-related inputs

---

## The reliable fix (use form scoping)

From your screenshots, the username/password inputs are inside the **login form**, not the cookie panel.

### Replace this ❌

```ts
page.locator('input[type="text"]').first()
```

### With this ✅

```ts
const loginForm = page.locator('form');

const usernameInput = loginForm.locator('input[type="text"]');
await usernameInput.waitFor({ state: 'visible', timeout: 30000 });
await usernameInput.fill(USERNAME);

const passwordInput = loginForm.locator('input[type="password"]');
await passwordInput.fill(PASSWORD);
```

This **automatically ignores** the cookie manager because it’s not inside the login form.

---

## Extra safety (recommended)

Sometimes there are multiple forms. You can be stricter:

```ts
const loginForm = page.locator('form').filter({
  has: page.locator('input[type="password"]')
});
```

Then:

```ts
const usernameInput = loginForm.locator('input[type="text"]');
const passwordInput = loginForm.locator('input[type="password"]');
```

This guarantees you’re in the right form.

---

## Why this will fix the timeout

* Cookie vendor search input is **outside the login form**
* It stays hidden forever
* Playwright was waiting for it to become visible
* By scoping to the form, Playwright now targets the real inputs

This exact error is a classic Playwright + cookie banner symptom.

## Optional: proactively close cookie banner (nice to have)

You don’t need this to fix login, but it helps later:

```ts
const acceptCookies = page.getByRole('button', { name: /accept/i });
if (await acceptCookies.count()) {
  await acceptCookies.first().click();
}
```

Do this **after login**, not before.
