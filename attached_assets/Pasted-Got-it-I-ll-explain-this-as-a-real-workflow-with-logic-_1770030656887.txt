## What this automation is responsible for

The automation has **one job only**:

> Log into People Planner, download three specific Excel exports using predefined templates, for a given branch and date range, and hand those files to your dashboard pipeline.

It does **not** interpret data.
It does **not** change configuration.
It does **not** touch areas, carers, or statuses.

---

## Global rules the automation follows

These rules are important because they simplify the logic and reduce breakage.

* Area is never changed. Default selection is always valid.
* Export Type is always Excel.
* Export Templates are explicitly selected by name.
* Branch is selected once per export.
* Dates are set only on exports that require them.
* Each export is independent. Failure in one does not silently affect others.

---

## Step 1: Login and session establishment

### Logic

Before doing anything, the bot must establish a valid authenticated session. Everything else depends on this.

### What happens

1. Open the People Planner login page.
2. Submit the Client ID.
3. Choose the internal People Planner account (not caregiver or client portals).
4. Submit username and password.
5. Confirm the dashboard loads.

### Why this matters

* If login fails, the job stops immediately.
* No retries on credentials. Fail fast and alert.

---

## Step 2: Move to Reports context

### Logic

All exports live under Reports. The bot always resets itself to the Reports tab before starting an export to avoid menu state issues.

### What happens

* Click Reports in the top navigation.
* Wait for the Reports page to fully load.

### Why this matters

Hover menus in this system are fragile. Resetting to Reports before each export makes navigation deterministic.

---

## Step 3: Visits export (Scheduling → Exports → Visits)

### Logic

Visits data is branch based and date bound. The export must use the correct template so the downstream parser remains stable.

### What happens

1. Navigate via hover:

   * Scheduling
   * Exports
   * Visits
2. Select the Visits export template by name.
3. Select the branch (Franchise).
4. Set start and end dates if required.
5. Confirm Export Type is Excel.
6. Trigger export and wait for file download.
7. Save file using a predictable name.

### Why this matters

* Template selection guarantees column structure.
* Branch selection aligns with your dashboard’s branch context.
* Deterministic filenames prevent the parser from guessing.

If the download does not start within a timeout, the export is marked as failed and logged.

---

## Step 4: CAREGivers export (CAREGivers → Exports → CAREGivers)

### Logic

This export provides reference data. It does not depend on dates and does not need area or individual filtering.

### What happens

1. Reset to Reports.
2. Navigate via hover:

   * CAREGivers
   * Exports
   * CAREGivers
3. Select the CAREGivers export template by name.
4. Select the branch.
5. Ensure Export Type is Excel.
6. Trigger export and save the file.

### Why this matters

* This file acts as a lookup table in your system.
* Keeping it branch scoped avoids cross-branch contamination.
* No dates keeps the logic simple and stable.

---

## Step 5: CAREGiver Availability export

### Logic

Availability is time bound and branch scoped. Like Visits, it must use a known template.

### What happens

1. Reset to Reports.
2. Navigate via hover:

   * CAREGivers
   * Exports
   * CAREGiver Availability
3. Select the Availability export template.
4. Select the branch.
5. Set start and end dates.
6. Confirm Export Type is Excel.
7. Trigger export and save the file.

### Why this matters

* Availability drives planning logic downstream.
* Dates ensure the file aligns with the dashboard’s reporting window.
* Leaving carers unselected ensures full coverage.

---

## Step 6: Handoff to dashboard logic

### Logic

Once all files are downloaded, the automation’s responsibility ends.

### What happens

* Files are placed in a known folder.
* Filenames follow a strict convention.
* Your existing ingestion logic:

  * Detects files
  * Parses them
  * Updates the database
  * Refreshes the dashboard

### Why this matters

This keeps automation and business logic fully separated. If People Planner changes, only the automation layer is touched.

## Error handling and safety logic

This is critical for a production setup.

* Each export is wrapped in:

  * Navigation timeout checks
  * Download timeout checks
* Failures are logged with:

  * Export name
  * Branch
  * Timestamp
* The job does not retry aggressively. One clean retry max.
* No export failure is silently ignored.

## How this runs operationally

* One browser session per run.
* No parallel logins.
