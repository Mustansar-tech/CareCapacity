## What this screen actually is (important)

This is the **Access portal selector**, and it is **not dynamic text** in the way Playwright’s `text=` selector expects.

Key details from the screenshot:

* The option is a **tile**, not a normal button
* The clickable area is a **div / anchor**, not a `<button>`
* The visible text:

  > “Sign in with Access People Planner Account”
* But the click target is the **tile container**, not the text node itself

That’s why:

```ts
page.click('text=Sign in with Access People Planner Account')
```

times out. The text exists visually, but it’s not a direct clickable element.

## Reliable selector strategy (this will work)

### Option 1 (best): Click the first tile

From the layout, “Access People Planner Account” is always the **first tile**.

```ts
const portalTile = page.locator('.portal-tile, .tile, .login-tile').first();
await portalTile.waitFor({ state: 'visible', timeout: 30000 });
await portalTile.click();
```

(Exact class name may vary, see Option 3 if needed.)

---

### Option 2: Click by partial text inside a container

Instead of `text=...`, do this:

```ts
const portalTile = page.locator('div', {
  hasText: 'Access People Planner'
});
await portalTile.waitFor({ state: 'visible', timeout: 30000 });
await portalTile.click();
```

This works because Playwright finds the **container div**, not the text node.

---

### Option 3: Click by icon + structure (very robust)

If text changes slightly in future, this is safest:

```ts
const tiles = page.locator('div').filter({
  has: page.locator('text=People Planner')
});
await tiles.first().click();
```

## Why this works (and the old one didn’t)

* `text=...` only matches **direct text nodes**
* Your tile is a **complex container**
* `hasText` matches anywhere inside the element
* Clicking the container triggers the navigation

This is the correct Playwright pattern for tile-based UIs.
