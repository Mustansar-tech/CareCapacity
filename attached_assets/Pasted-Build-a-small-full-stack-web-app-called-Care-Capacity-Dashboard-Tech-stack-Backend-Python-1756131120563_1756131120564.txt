Build a small full‑stack web app called “Care Capacity Dashboard”.

Tech stack:
- Backend: Python (FastAPI), pandas, openpyxl. One process; no DB required.
- Frontend: React + Vite + Tailwind (or simple CSS), Recharts for charts.
- Deployment: run with `uvicorn main:app --host 0.0.0.0 --port 8000`.

Core user flow:
1) User uploads THREE Excel files:
   a) “Availability Export.xlsx” (sheet: CAREGiver Availability)
   b) “Care Pro Guaranteed Hours.xlsx” (sheet: Data)
   c) “client_demand.xlsx” with columns: Date (DD/MM/YYYY) and Required Client Hours (number)

2) Backend merges & cleans the files using THESE EXACT RULES (do not improvise):
   - Robust name matching:
     • Normalize names by lowercasing and removing titles and tags like (NL) (GH), punctuation, and extra spaces.
     • Token-sort the remaining words and use fuzzy matching (≥0.7) to map Availability names to Guaranteed Hours names.
   - Contracted Daily Hours = Contracted Weekly Hours ÷ Days Available,
     where “Days Available” is the count of UNIQUE dates an employee appears in Availability (any status counts).
   - Group by Employee + Date (Option 2 – Enhanced):
     • Keep all non-overlapping statuses; concatenate time windows for that status.
     • If statuses overlap/conflict, apply priority (highest wins): 
       Maternity/Paternity > Sick > Holiday > Compassionate Leave > Other Unavailable > Pre‑Agreed Appointment > Available.
   - Capacity adjustments:
     • Compute per-status hours from Start/End (fallback to exported Hours).
     • Compute total leave hours for the date; CAP at Contracted Daily Hours.
     • Available hours for the day = Contracted Daily Hours − capped leave (minimum 0).
     • Leave rows always have Net Capacity = 0.
     • Available row gets Net Capacity = adjusted Available hours.
   - Output columns for “Cleaned” data:
     Employee Name, Contracted Weekly Hours, Contracted Daily Hours, Date, Status, Time Windows, Hours, Net Capacity, Notes.

3) Aggregation:
   - Build a “DailySummary” table with columns:
     Date, Available_Hours (sum Hours where Status=Available),
     Net_Capacity (sum of Net Capacity),
     Sickness (sum Hours where Status=Sick),
     Holidays (sum Hours where Status=Holiday).
   - Merge client demand on Date (parse day‑first); rename “Required Client Hours” → Client_Required.
   - Gap = Net_Capacity − Client_Required.
   - Derive a Status label for the day: “Sufficient” if Gap ≥ 0 else “Shortage”.

API design:
- POST /api/process
  Body: multipart/form-data with three files (availability, guaranteed, demand).
  Behavior: run the pipeline, return JSON with:
    { 
      kpis: { netCapacitySum, clientRequiredSum, gapSum, sicknessSum, holidaysSum },
      dailySummary: [ {date, availableHours, netCapacity, clientRequired, gap, status} ],
      employeesByDate: { "YYYY-MM-DD": [ {employeeName, status, timeWindows, contractedDailyHours, hours, netCapacity, notes} ] }
    }
  Also save an Excel export “capacity_dashboard.xlsx” with sheets:
    Cleaned, DailySummary, EmployeeDailyDetail (minimal drilldown columns).
- GET /api/export
  Returns the latest “capacity_dashboard.xlsx” as a download.

Frontend requirements:
- Page layout tabs: Overview | Daily Capacity | Export.
- “Overview” shows KPI cards:
  • Net Capacity (sum)  • Client Required (sum)  • Capacity Gap (sum)
  • Sickness (sum)      • Holidays (sum)
- “Daily Capacity”:
  • A table with columns: Date, Available, Net Capacity, Required, Gap, Status (Sufficient/Shortage with colored pill).
  • Clicking a row shows a drilldown table below for that date with columns:
    Employee, Status, Time Window(s), Contracted Daily, Hours, Net Capacity, Notes.
- “Export”:
  • Button to download the generated “capacity_dashboard.xlsx”.
- Upload UX:
  • Three file inputs (Availability, Guaranteed, Demand) and a single “Process” button.
  • Show a toast on success or validation errors (e.g., missing sheet names/columns).

Validation & edge cases (implement):
- Reject if required sheets are missing:
  • Availability must have columns: CAREGiver Name, Start Date, Start Time, End Time, Type, Hours (optional), Notes (optional).
  • Guaranteed must have columns: Actual Employee Name, Actual Employee Hours Per Week.
  • Demand must have columns: Date, Required Client Hours.
- Parse dates as day‑first (DD/MM/YYYY).
- Name matching:
  • Normalization: remove parentheses blocks, punctuation, titles (Mr, Mrs, Miss, Ms, Dr), token-sort.
  • Fuzzy match threshold 0.7; if unmatched, drop from output and list under a “Unmatched employees” warning in the response.
- Time calculation: compute duration from Start/End when Hours is missing; if End < Start, assume overnight and add 24h.
- Leave capping: total leave cannot exceed Contracted Daily Hours.
- All numeric outputs rounded to 2 decimals.
