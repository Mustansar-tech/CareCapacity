## Why your selector fails (root cause)

In ASP.NET WebForms, inputs usually end up with IDs like:

```
ctl00_MainContent_txtClientID
```

or similar, and often:

* no `name="ClientID"`
* no simple `id="ClientID"`

Visually you see “Client ID”, but the DOM attribute is different.

So this will **never match**:

```ts
input[name="ClientID"], input#ClientID
```

That’s why you get a timeout even though the field is right there.

---

## The correct way to target this field

You should target it by **label proximity** or **form structure**, not by name.

### ✅ Most reliable selector for this page

The Client ID input is the **only text input inside the login form** on that page.

So this works reliably:

```ts
const clientIdInput = page.locator('form input[type="text"]').first();

await clientIdInput.waitFor({ state: 'visible', timeout: 30000 });
await clientIdInput.fill(CLIENT_ID);
```

This matches what you see in the screenshot exactly.

---

## Login button selector (also important)

The button is not a `<button>` element.
It’s an ASP.NET styled input.

So use:

```ts
await page.locator('form input[type="submit"], form button').first().click();
```
