## What is actually happening (root cause)

After you enter:

* Client ID ✅
* Select “Access People Planner Account” ✅

You are **sometimes redirected to the public marketing site**:

> `peopleplanner.com / PeoplePlanner – Residential`

That page:

* Has cookie banners
* Has no username/password fields
* Is a brochure site, not the app
* Will **never** show `input[type="password"]`

So Playwright is doing the right thing by timing out.
The credentials page simply does not exist on that URL.

This is not a selector issue anymore.
This is a **navigation / redirect issue**.

---

## Why this happens (important)

Access uses **multiple domains**:

* ✅ App domain (correct):

  ```
  https://servicea064-appgrp13.peopleplanner.biz/...
  ```
* ❌ Marketing site (wrong):

  ```
  https://www.peopleplanner.com/...
  ```

When:

* cookies are missing
* session state is incomplete
* or headless behaves slightly differently

…the portal tile click sometimes sends you to the **marketing site instead of the app**.

Humans don’t notice because browsers already have cookies.
Headless does not.

---

## Key takeaway (this changes the logic)

You **must guard against landing on the wrong domain**
and force navigation back to the **application login**.

---

## The correct, robust solution (this WILL fix it)

### 1️⃣ After clicking the portal tile, verify the domain

Immediately after:

```ts
await tiles.first().click();
```

Add this:

```ts
await page.waitForTimeout(1500);

const currentUrl = page.url();

if (currentUrl.includes('peopleplanner.com') && !currentUrl.includes('.biz')) {
  // We landed on marketing site, not the app
  await page.goto(
    'https://servicea064-appgrp13.peopleplanner.biz/Common/Security/Login.aspx',
    { waitUntil: 'domcontentloaded' }
  );
}
```

This forces you back into the **real application**.

---

### 2️⃣ THEN wait for the password field

Now this selector finally makes sense again:

```ts
const passwordInput = page.locator('input[type="password"]');
await passwordInput.waitFor({ state: 'visible', timeout: 30000 });
```

On the app domain, it will appear.

On the marketing site, it never would.
