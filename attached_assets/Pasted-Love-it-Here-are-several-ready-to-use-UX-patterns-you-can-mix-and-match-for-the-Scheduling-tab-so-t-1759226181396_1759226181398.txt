Love it. Here are several ready-to-use UX patterns you can mix and match for the Scheduling tab so the team can assign fast, confidently, and without touching the database.

A) Layout options (pick one primary, keep others as toggles)

Employee-centric (your current idea, polished)

Left: Date switcher + Employee search.

Center: Selected employee’s Run (ordered cards) with availability strips behind the timeline.

Right: Best Matches (ranked list).

Great when schedulers work one CP at a time.

Map + Timeline split

Left: Mini map with CP home, clients, and the current run path.

Right: Vertical timeline of the CP’s day.

Best when minimizing travel and confirming local clusters at a glance.

Two-pane Compare

Left: CP-A run; Right: CP-B run; Bottom: shared Best Matches list.

Drag a visit card onto either run; scores update live for both.

Ideal when deciding who is the better fit.

Visit-first “Who’s best?”

Top: Unassigned visits for the day.

Select one visit → Right panel shows ranked CPs with their incremental score and feasibility explanation.

Great during high volume: “We must place this 10:30 visit—who’s best?”

Kanban by time blocks

Columns are your standard blocks (08:00–09:00, 09:15–10:15, …).

Within each column, cards grouped by neighborhood (e.g., “Stepps”, “Bearsden”).

Drag visit → drop onto a CP swimlane inside the column; system checks feasibility.

B) “Best Matches” card design (compact and decisive)

Each candidate shows, at a glance:

Client · 10:30–11:30

+Travel: 7 min (from prior) / 6 min (to next)

Gap impact: +15 min idle

Window fit: inside 09:00–12:00 (margin: 30 min)

Day load after assign: 6h45/9h

Score badge: 8.7 (Tight run)

CTA: Assign · Preview in run

Tiny badges:

🏠 “Good home start” (only if first) / “Good home finish” (only if last)

📍 “Same area” (cluster match)

🔁 “Pairs well with meds” (if back-to-back routine patterns matter)

Explainability tooltip (1 line):

Score = 40% tightness + 35% travel + 15% window slack + 10% home proximity.

C) Quick actions the team will love

1-click Assign: inserts at the best spot automatically.

Hold to choose: long-press (or “▾” next to Assign) opens alternate insertion options (before/after specific visit).

“Pin” a visit in the run so future re-ranking won’t move it.

Undo / Redo stack (visible at top).

“Keep under 20 min travel” filter toggle on Best Matches.

Neighborhood filter (chips: Stepps, Bearsden, Easterhouse…).

Keyboard shortcuts: ↑/↓ to move through ranked list, Enter to assign.

D) Visual signals (reduce thinking time)

Run tightness bar under the timeline (green = dense, amber = small gaps, red = large gaps).

Care time meter (0–9h) with a thin travel stripe overlaid: shows “care vs travel” balance.

Availability conflicts: red overlay for out-of-window; never allow assignment if it’s red.

Travel dots along the run with hover tooltip “A→B 6 min”.

Multi-hour visit cards taller with a subtle “2h” badge.

Unallocated tray at the bottom: visits grouped by time, with count + reason (“no CP window”, “exceeds care cap”, “travel > 25 min”).

E) Ranking knobs (visible, simple)

A small “Scoring” panel (icon ⚙️):

Tightness: 40% (slider)

Travel: 35%

Window slack: 15%

Home proximity: 10%

Max travel per hop: 25 min (hard cap)

Buffer before/after visit: 5 min

Care cap: 9h

Changing sliders re-ranks Best Matches in real time (no DB writes).

F) Feasibility rules (always enforced)

Visit must fully fit inside at least one employee availability window including travel to/from neighbors.

Total care minutes after insertion ≤ 540.

First/last leg uses home↔client travel; internal legs use client↔client only.

No shifting of the client’s planned times—ever.

If rejected, the card shows why (e.g., “exceeds cap by 45 min”, “arrive 4 min late (needs 5 min buffer)”, “travel 31>25 min cap”).

G) Day workflow patterns (for the team)

Morning triage

Use Visit-first “Who’s best?” to place early unallocated visits.

Switch to Employee-centric to tighten each CP’s run and fill gaps.

Mid-day changes

Live “What changed?” drawer: new cancellations, hospitalizations, CP sickness.

Re-rank Best Matches immediately; show a “safe reflow” button that only suggests swaps that preserve all constraints.

End of day

Export Run Sheet (print/PDF): CP name, start/end, ordered clients, travel times, special notes.

Export Exceptions: still-unallocated visits and reasons.

H) Data discipline (Excel-only, no DB pollution)

Read-only day loader pulls:

Visits from Guaranteed Hours (Planned Start/End first).

Employee availability from Availability Export.

Home postcodes from CG Data (for travel only).

No visit writes while planning.

Optional “Commit Plan” stores minimal edges {date, employeeId, visitId, index}.

If you don’t want persistence at all, offer Download Plan (.xlsx/.csv) for distribution.

I) Minimal metrics that matter

Coverage: assigned care hours / required care hours.

Avg run travel per CP (mins).

% visits within 10 min of previous (tightness KPI).

Unallocated count by reason (window, travel, cap).

These sit in a skinny header; they change live as you assign.

J) Edge cases handled clearly

Overlapping visits for a CP → hard stop; show which one conflicts.

Multi-hour visits → card locks 2–3 blocks; insertion checks both ends.

Night visits (if any) → dark theme rows from 20:30+.

No home coords → badge “No home location (using district center)”.

Recommended default: “Employee-centric + Best Matches” with a Map toggle

It fits your working style (pick CP → see best clients), stays clean (Excel-only), and gives instant, explainable decisions. Add the Map toggle for tricky travel days, and keep the Visit-first mode as a second tab for morning triage.
